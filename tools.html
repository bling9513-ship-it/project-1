실무 · 모의해킹 명령어 치트시트

        
카테고리 필터와 키워드 검색 · 카드의 복사 버튼으로 명령 전체를 복사

살아 있는 호스트만 추리기

        Nmap
      

      
점검 대역에서 응답하는 호스트를 먼저 확정합니다. 포트 스캔 전에 자산 범위를 좁힐 때 씁니다.

      

        
Nmap

        
nmap -sn 10.0.1.0/24 -oG - | awk '/Up$/{print $2}'

      

      
주의ICMP를 막는 망에서는 -sn이 아무것도 못 찾습니다. -PS22,80,443 -PE를 함께 주거나 ARP 기반(-PR)으로 확인하세요.

    

    

      

        
서비스·버전 핑거프린팅

        Nmap
      

      
상위 1000개 포트에서 열린 서비스의 제품·버전과 기본 스크립트 결과를 한 번에 모읍니다.

      

        
Nmap

        
nmap -sV -sC -T4 --top-ports 1000 10.0.1.10 -oN sv_scan.txt

      

      
주의-sC는 기본 NSE 스크립트를 돌리므로 로그에 흔적이 남습니다. 운영 중인 서버라면 점검 허가 범위와 시간 창을 먼저 확인하세요.

    

    

      

        
전체 65535 포트 고속 스캔

        Nmap
      

      
기본 스캔이 놓치는 상위 포트 밖 서비스(관리 콘솔, 개발 포트)를 찾습니다.

      

        
Nmap

        
nmap -p- --min-rate 2000 -T4 -Pn 10.0.1.10 -oN allports.txt

      

      
주의--min-rate 2000은 패킷을 초당 2000개까지 밀어냅니다. IDS·IPS가 있는 구간에서는 알람이 뜨고 회선에도 부담이 되니 내부 점검망에서만 쓰세요.

    

    

      

        
웹 서버 정보·허용 메서드

        Nmap
      

      
HTTP 응답 헤더, 타이틀, OPTIONS 응답으로 서버 종류와 위험 메서드(PUT·DELETE·TRACE) 허용 여부를 봅니다.

      

        
Nmap

        
nmap -p 80,443,8080,8443 --script http-title,http-headers,http-methods 10.0.1.10

      

      
주의허용 메서드에 PUT이 있으면 업로드 취약점으로 이어질 수 있습니다. 실제 요청은 curl -X OPTIONS로 한 번 더 확인하세요.

    

    

      

        
SMB 취약점·공유 열거

        Nmap
      

      
445 포트에서 OS 정보, 공유 목록, 알려진 원격 실행 취약점(MS17-010 등)을 확인합니다.

      

        
Nmap

        
nmap -p 445 --script smb-os-discovery,smb-enum-shares,smb-vuln-ms17-010 10.0.1.20

      

      
주의스크립트 결과가 "VULNERABLE"이어도 실제 익스플로잇 시도는 하지 않습니다. 취약 여부만 근거로 보고하고 패치 일정을 잡으세요.

    

    

      

        
UDP 상위 포트 점검

        Nmap
      

      
DNS·SNMP·NTP 같은 UDP 서비스는 TCP 스캔에 보이지 않습니다. 응답이 느리므로 상위 포트만 짧게 봅니다.

      

        
Nmap

        
nmap -sU --top-ports 50 --max-retries 1 --host-timeout 3m 10.0.1.10

      

      
주의open|filtered는 응답이 없어 열림/차단을 구분하지 못한 상태입니다. SNMP(161)는 community 문자열 없이는 확정할 수 없습니다.

    

    

      

        
SUID·SGID 실행 파일 전수 조사

        Linux 점검
      

      
소유자 권한으로 실행되는 파일을 찾습니다. 권한 상승 경로를 찾는 1차 단서입니다.

      

        
find

        
find / -xdev \( -perm -4000 -o -perm -2000 \) -type f -ls 2>/dev/null

      

      
주의기본 배포판에 없는 바이너리(예: /usr/bin/find, /usr/bin/vim)에 SUID가 걸려 있으면 거의 확실히 이상 징후입니다. 패키지 소유 여부를 dpkg -S·rpm -qf로 대조하세요.

    

    

      

        
누구나 쓰기 가능한 파일 찾기

        Linux 점검
      

      
other 쓰기 권한이 열린 파일을 찾습니다. 서비스가 참조하는 설정·스크립트가 걸리면 변조 경로가 됩니다.

      

        
find

        
find / -xdev -type f -perm -0002 -ls 2>/dev/null | head -50

      

      
주의/tmp, /var/tmp 아래 임시 파일은 정상일 수 있습니다. 실제 위험은 root 소유 서비스 설정 파일에 o+w가 열린 경우입니다.

    

    

      

        
capability가 부여된 바이너리

        Linux 점검
      

      
SUID 대신 프로세스 단위 권한(capability)을 받은 실행 파일을 확인합니다. 최근 리눅스 권한 상승의 주요 통로입니다.

      

        
getcap

        
getcap -r / 2>/dev/null

      

      
주의cap_setuid+ep, cap_sys_admin+ep, cap_dac_read_search+ep는 사실상 root급입니다. 배포판 기본값(예: ping의 cap_net_raw)과 비교해 추가된 항목만 보세요.

    

    

      

        
예약 작업(cron·systemd timer) 점검

        Linux 점검
      

      
주기 실행 작업은 지속성 확보와 권한 상승의 단골 경로입니다. 사용자 cron과 시스템 타이머를 함께 봅니다.

      

        
cron

        
crontab -l 2>/dev/null; sudo ls -l /etc/cron.* /var/spool/cron/crontabs 2>/dev/null; systemctl list-timers --all --no-pager | head -30

      

      
주의root cron이 실행하는 스크립트가 사용자 쓰기 가능하면 그 파일 하나로 root 권한을 얻습니다. 스크립트 경로의 소유자·권한까지 같이 확인하세요.

    

    

      

        
리슨 포트와 소유 프로세스

        Linux 점검
      

      
지금 외부에서 접근 가능한 포트와 그 포트를 잡고 있는 프로세스를 매핑합니다.

      

        
ss

        
sudo ss -tulpn

      

      
주의0.0.0.0:*·[::]:*는 모든 인터페이스에 열린 상태입니다. 방화벽으로 막혀 있어도 내부에서는 노출되므로 127.0.0.1: 바인딩이 필요한 서비스를 구분하세요.

    

    

      

        
로그인 성공·실패 기록

        Linux 점검
      

      
최근 로그인 이력과 실패 기록으로 무차별 대입·비정상 접속을 확인합니다.

      

        
last

        
last -ai | head -20; echo '--- 실패 ---'; sudo lastb | head -20

      

      
주의성공 기록에 낯선 IP·시간대가 있으면 lastlog, /var/log/auth.log(또는 journald)에서 해당 세션의 명령 이력을 이어서 확인하세요.

    

    

      

        
sudo 권한과 NOPASSWD 설정

        Linux 점검
      

      
계정이 어떤 명령을 어떤 사용자로 실행할 수 있는지 확인합니다. 과도한 sudo 규칙은 즉시 권한 상승으로 이어집니다.

      

        
sudo

        
sudo -l -U deploy; sudo grep -rE 'NOPASSWD|ALL=\(ALL\)' /etc/sudoers /etc/sudoers.d 2>/dev/null

      

      
주의NOPASSWD로 vi·find·tar·less 같은 편집·실행 도구를 허용하면 셸을 띄울 수 있습니다. 허용 목록은 절대 경로와 인자까지 제한해야 안전합니다.

    

    

      

        
보안 응답 헤더 한눈에 보기

        웹·curl
      

      
CSP·HSTS·X-Frame-Options·nosniff가 실제 응답에 실려 있는지 확인합니다.

      

        
curl

        
curl -sSI https://target.example.com | grep -iE '^(server|content-security-policy|strict-transport-security|x-frame-options|x-content-type-options|referrer-policy)'

      

      
주의헤더가 없다고 곧 취약점은 아니지만, XSS·클릭재킹 대응 수준을 판단하는 근거가 됩니다. 리다이렉트되는 도메인마다 따로 확인하세요.

    

    

      

        
리다이렉트·TLS 체인 추적

        웹·curl
      

      
http→https 전환 과정에서 인증서가 바뀌거나 중간 도메인으로 튀는지 확인합니다.

      

        
curl

        
curl -sSIL --max-redirs 5 http://target.example.com

      

      
주의첫 응답이 https가 아니라면 HSTS가 없는 한 최초 요청은 평문입니다. 민감 쿠키는 Secure 속성이 있어야 이 구간에서 새지 않습니다.

    

    

      

        
세션 쿠키 속성 점검

        웹·curl
      

      
로그인 응답의 Set-Cookie에 HttpOnly·Secure·SameSite가 붙었는지 확인합니다.

      

        
curl

        
curl -sSI https://target.example.com/login | grep -i '^set-cookie'

      

      
주의세션 쿠키에 HttpOnly가 없으면 XSS 한 번으로 세션이 탈취됩니다. SameSite=None이면 Secure가 반드시 함께 있어야 합니다.

    

    

      

        
허용 HTTP 메서드 확인

        웹·curl
      

      
OPTIONS 응답으로 서버가 열어 둔 메서드를 확인합니다. PUT·DELETE·TRACE는 설정 실수를 드러냅니다.

      

        
curl

        
curl -sS -i -X OPTIONS https://target.example.com/ | head -20

      

      
주의Allow 헤더에 TRACE가 있으면 XST(Cross-Site Tracing) 위험이 있고, PUT이 열려 있으면 업로드 경로를 우선 점검하세요.

    

    

      

        
경로 정규화 우회 점검

        웹·curl
      

      
인코딩된 ../가 정적 파일 서버에서 상위 디렉터리로 해석되는지 확인합니다.

      

        
curl

        
curl -sS --path-as-is "https://target.example.com/static/..%2f..%2fetc/passwd" | head -5

      

      
주의--path-as-is가 없으면 curl이 경로를 미리 정규화해 버려 재현이 안 됩니다. 응답 코드와 본문 첫 줄을 함께 보세요.

    

    

      

        
JSON API에 페이로드 파일로 요청

        웹·curl
      

      
따옴표·중괄호가 섞인 복잡한 페이로드는 파일로 분리해 보냅니다. 셸 인용 오류를 없애고 재현성을 높입니다.

      

        
curl

        
curl -sS -i -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" --data @payload.json https://target.example.com/api/login

      

      
주의응답 코드만 보지 말고 -i로 헤더와 함께, 오류 메시지에 내부 경로·SQL이 노출되는지 확인하세요. 토큰은 셸 히스토리에 남지 않도록 환경변수로 넘깁니다.

    

    

      

        
민감 경로·정책 파일 존재 확인

        웹·curl
      

      
robots.txt, security.txt, .git/HEAD 같은 파일이 공개돼 있는지 상태 코드만으로 빠르게 훑습니다.

      

        
for

        
for p in robots.txt sitemap.xml .well-known/security.txt .git/HEAD .env; do printf '%-28s %s\n' "$p" "$(curl -sS -o /dev/null -w '%{http_code}' https://target.example.com/$p)"; done

      

      
주의.git/HEAD가 200이면 소스 저장소가 통째로 노출된 것입니다. .env 200은 자격증명 유출로 직결되므로 즉시 보고 대상입니다.

    

    

      

        
시간 기반 블라인드 SQLi 확인

        웹·curl
      

      
응답 내용이 바뀌지 않는 블라인드 구간에서 지연 시간으로 주입 가능성을 판별합니다.

      

        
curl

        
curl -sS -o /dev/null -w '%{time_total}\n' "https://target.example.com/item?id=1%27%20AND%20SLEEP(3)--"

      

      
주의3초 지연이 일관되게 나와야 신호입니다. 네트워크 지연과 구분하려면 같은 요청을 3회 반복하고, 정상 파라미터 요청의 기준 시간과 비교하세요.

    

    

      

        
로컬 관리자·계정 확인

        Windows·AD
      

      
대상 호스트의 로컬 관리자 그룹과 전체 로컬 계정을 확인합니다.

      

        
cmd

        
net localgroup administrators & net user & whoami /priv

      

      
주의whoami /priv에서 SeImpersonatePrivilege가 보이면 Potato 계열 권한 상승이 가능한 환경입니다. 실제 공격은 하지 말고 설정 오류로 보고하세요.

    

    

      

        
도메인 관리자 그룹 구성원

        Windows·AD
      

      
도메인·엔터프라이즈 관리자 그룹의 현재 구성원을 확인합니다. 권한이 과하게 부여된 계정을 찾는 첫 단계입니다.

      

        
cmd

        
net group "Domain Admins" /domain & net group "Enterprise Admins" /domain & net group "Account Operators" /domain

      

      
주의서비스 계정이 Domain Admins에 들어 있으면 그 계정이 침해되는 순간 도메인 전체가 넘어갑니다. 업무용·서비스 계정의 분리를 권고하세요.

    

    

      

        
SPN 보유 계정(Kerberoast 대상) 조회

        Windows·AD
      

      
서비스 주체 이름이 등록된 계정을 뽑습니다. 오프라인 크래킹에 쓰이는 티켓 발급 대상입니다.

      

        
PowerShell

        
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName | Select-Object SamAccountName,ServicePrincipalName

      

      
주의서비스 계정의 비밀번호가 길고 주기적으로 교체되는지가 핵심입니다. 25자 이상 무작위 암호를 권고하고, krbtgt 계정의 이중 재설정도 함께 점검하세요.

    

    

      

        
LocalSystem으로 도는 서비스 경로

        Windows·AD
      

      
SYSTEM 권한으로 실행되는 서비스의 실행 파일 경로를 확인합니다. 쓰기 가능한 경로에 있으면 권한 상승 지점입니다.

      

        
PowerShell

        
Get-CimInstance Win32_Service | Where-Object {$_.StartName -like '*LocalSystem*'} | Select-Object Name,StartMode,PathName | Format-List

      

      
주의경로에 공백이 있고 따옴표가 없는 항목(C:\Program Files\...)은 unquoted service path 문제입니다. 각 경로의 디렉터리 ACL을 icacls로 확인하세요.

    

    

      

        
로그온 실패 4625 집계

        Windows·AD
      

      
보안 로그에서 로그온 실패(4625)를 모아 무차별 대입·자격증명 스터핑 시도를 확인합니다.

      

        
PowerShell

        
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4625} -MaxEvents 50 | Group-Object {$_.Properties[5].Value} | Sort-Object Count -Descending | Select-Object Count,Name

      

      
주의4625는 기본 감사 정책에서 켜져 있어야 기록됩니다. 짧은 시간에 여러 계정으로 퍼지는 실패는 password spray 패턴입니다.

    

    

      

        
SMB 공유·접속 세션 확인

        Windows·AD
      

      
공유 목록과 현재 접속 중인 세션을 확인합니다. 불필요한 쓰기 공유와 원격 접속 흔적을 찾습니다.

      

        
PowerShell

        
Get-SmbShare | Select-Object Name,Path,Description | Format-Table -Auto; Get-SmbSession | Select-Object ClientComputerName,ClientUserName,NumOpens

      

      
주의IPC$ 외에 Everyone 쓰기 권한이 있는 공유는 랜섬웨어 확산 경로가 됩니다. 공유 ACL은 Get-SmbShareAccess로 함께 확인하세요.

    

    

      

        
특정 호스트 트래픽 저장

        네트워크·tcpdump
      

      
대상 호스트와 오가는 패킷을 파일로 남겨 나중에 Wireshark로 분석합니다.

      

        
tcpdump

        
sudo tcpdump -i any -nn -s 0 host 10.0.1.10 -w cap.pcap

      

      
주의-s 0은 패킷 전체를 저장합니다(기본은 262144바이트로 충분하지만 명시가 안전). 캡처 파일에는 개인정보·자격증명이 담길 수 있어 보관 기한과 접근 권한을 정해 두세요.

    

    

      

        
HTTP 요청 라인 실시간 확인

        네트워크·tcpdump
      

      
암호화되지 않은 HTTP 구간에서 어떤 경로로 요청이 오가는지 실시간으로 봅니다.

      

        
tcpdump

        
sudo tcpdump -i any -nn -A 'tcp port 80' | grep --line-buffered -E '^(GET|POST|HEAD|Host:)'

      

      
주의평문 HTTP에서 Authorization 헤더나 세션 쿠키가 그대로 보이면 그 자체가 유출입니다. 운영 서비스라면 즉시 TLS 적용 대상으로 보고하세요.

    

    

      

        
DNS 질의 감시

        네트워크·tcpdump
      

      
내부 호스트가 어떤 도메인을 조회하는지 확인합니다. 악성 도메인·터널링 징후를 찾는 기본 수단입니다.

      

        
tcpdump

        
sudo tcpdump -i any -nn -vv 'udp port 53' -c 100

      

      
주의-vv로 질의 이름까지 보입니다. 길고 무작위한 서브도메인이 반복되면 DNS 터널링을 의심하고, 같은 이름의 응답 TTL·레코드 타입(TXT)도 함께 보세요.

    

    

      

        
pcap에서 SYN 패킷만 추출

        네트워크·tcpdump
      

      
저장한 캡처에서 연결 시도(SYN)만 걸러 스캔·접속 시도를 빠르게 추립니다.

      

        
tcpdump

        
tcpdump -nn -r cap.pcap 'tcp[13] & 2 != 0' -c 50

      

      
주의같은 출발지에서 여러 포트로 SYN만 뿌리고 ACK가 없으면 스캔입니다. -c로 개수를 제한해 출력이 넘치지 않게 하세요.

    

    

      

        
ARP 스푸핑 징후 찾기

        네트워크·tcpdump
      

      
같은 IP에 대해 서로 다른 MAC이 응답하는지 확인합니다. 내부 중간자 공격의 대표 신호입니다.

      

        
tcpdump

        
sudo tcpdump -i eth0 -nn arp -c 200 | awk '{print $2, $NF}' | sort | uniq -c | sort -rn | head

      

      
주의게이트웨이 IP에 두 개 이상의 MAC이 매핑되면 스푸핑을 의심합니다. 스위치 포트 보안·동적 ARP 검사(Dynamic ARP Inspection) 설정도 함께 확인하세요.

    

    

      

        
인증서 만료일·SAN 확인

        OpenSSL·SSH
      

      
서버가 실제로 내미는 인증서의 주체, 발급자, 유효기간, 대체 이름(SAN)을 확인합니다.

      

        
echo

        
echo | openssl s_client -connect target.example.com:443 -servername target.example.com 2>/dev/null | openssl x509 -noout -subject -issuer -dates -ext subjectAltName

      

      
주의-servername을 빼면 SNI 없이 접속해 다른 인증서를 받을 수 있습니다. 만료가 임박했거나 SAN에 실제 도메인이 빠져 있으면 브라우저 경고로 이어집니다.

    

    

      

        
TLS 버전·암호 스위트 확인

        OpenSSL·SSH
      

      
구버전 TLS(1.0/1.1)나 취약 암호 스위트가 아직 허용되는지 확인합니다.

      

        
OpenSSL

        
openssl s_client -connect target.example.com:443 -tls1_2 </dev/null 2>&1 | grep -E 'Protocol|Cipher|Verify return code'

      

      
주의TLS 1.0/1.1은 폐기 대상입니다. Verify return code: 0이 아니면 체인 문제이므로 중간 인증서 누락 여부를 확인하세요.

    

    

      

        
파일 무결성 검증

        OpenSSL·SSH
      

      
배포 파일이 배포처가 공개한 해시와 일치하는지 확인합니다. 공급망 침해를 걸러내는 가장 빠른 방법입니다.

      

        
sha256sum

        
sha256sum artifact.tar.gz; sha256sum -c SHA256SUMS; openssl dgst -sha256 artifact.tar.gz

      

      
주의해시 값은 파일을 받은 경로가 아닌 공식 공지·서명된 릴리스 노트에서 가져와야 의미가 있습니다. GPG 서명(.asc)이 있으면 서명 검증까지 하세요.

    

    

      

        
파일 암호화·복호화

        OpenSSL·SSH
      

      
전달용 파일을 비밀번호 기반(AES-256)으로 암호화하고 다시 풉니다.

      

        
OpenSSL

        
openssl enc -aes-256-cbc -pbkdf2 -iter 200000 -salt -in plain.txt -out plain.enc
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in plain.enc -out plain.txt

      

      
주의-pbkdf2와 높은 -iter를 빼면 옛 방식(단순 MD5 키 유도)으로 떨어집니다. 암호는 파일과 다른 채널(전화·메신저)로 전달하세요.

    

    

      

        
SSH 공개키 지문·길이 확인

        OpenSSL·SSH
      

      
키 파일의 지문과 비트 길이를 확인해 서버에 등록된 키와 같은지 대조합니다.

      

        
ssh-keygen

        
ssh-keygen -lf ~/.ssh/id_ed25519.pub; ssh-keygen -lf ~/.ssh/id_rsa.pub

      

      
주의RSA 2048비트 이하는 교체 대상입니다. 지문을 대조할 때는 앞뒤 몇 글자가 아니라 전체 지문을 비교하세요.

    

    

      

        
SSH 접속 실패 원인 추적

        OpenSSL·SSH
      

      
키 인증이 거부될 때 어느 단계에서 끊기는지 상세 로그로 확인합니다.

      

        
ssh

        
ssh -vvv -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes user@10.0.1.10 2>&1 | grep -E 'Offering|Authentications that can continue|Permission denied|Server accepts key'

      

      
주의Offering에 원하는 키가 없으면 ssh-agent가 다른 키를 먼저 내미는 것입니다. 서버 권한은 ~/.ssh 700, authorized_keys 600이어야 합니다.
